# Пробное подключение Enable Banking

Проверка читает собственные банковские счета и проведённые операции EUR за
последние 7 дней. Она запускается отдельно от budget-tracker, не читает `.env`,
не подключается к MongoDB и не импортирует операции. Автосинхронизация ещё не
включена.

## Регистрация

В кабинете Enable Banking создать Production application для личного
некоммерческого использования. Указать название, описание, контактный email,
адрес возврата, страницы условий и обработки данных. Использовать режим
`Generate outside the browser and import public certificate`.

Страницы находятся в `public/banking/` и попадут в сборку Vite. Перед настоящей
авторизацией их нужно опубликовать вместе с изменением `public/sw.js`, которое
исключает банковские страницы из офлайн-кеша.

Для текущего сайта:

- Redirect: `https://weary-ninette-vberezhnykh-9a11187e.koyeb.app/banking/callback.html`
- Privacy: `https://weary-ninette-vberezhnykh-9a11187e.koyeb.app/banking/privacy.html`
- Terms: `https://weary-ninette-vberezhnykh-9a11187e.koyeb.app/banking/terms.html`

Ключ `server/.banking/private.pem` и публичный сертификат
`server/.banking/public.crt` подготовлены локально. Каталог исключён из Git.
В форму передаётся только публичный сертификат. Приватный ключ не публикуется,
не передаётся в браузер и не добавляется в переменные фронтенда.

После регистрации использовать `Activate by linking accounts` и подтвердить
свои счета в банке. Этот шаг активирует restricted mode и список разрешённых
счетов. Для чтения через API потом нужно отдельное согласие.

## Конфигурация и запуск

Создать `server/.banking/config.json`:

```json
{
  "applicationId": "UUID из кабинета Enable Banking",
  "privateKeyPath": "private.pem",
  "redirectUrl": "https://weary-ninette-vberezhnykh-9a11187e.koyeb.app/banking/callback.html",
  "country": "CY",
  "bank": "Bank of Cyprus"
}
```

Для Revolut использовать точные `bank` и `country` из каталога провайдера;
проверенный в каталоге основной вариант — `Revolut`, `LT`. Доступность
конкретного счёта определяется банковским подтверждением.

Из корня проекта:

```shell
node server/banking-trial.js --config server/.banking/config.json --check
node server/banking-trial.js --config server/.banking/config.json --connect
```

`--check` читает только статус приложения и каталог банка. `--connect` печатает
ссылку авторизации. После подтверждения в банке страница возврата предлагает
скопировать ответ. Вставить его в ожидающий терминал: ввод скрыт.

Если терминал не поддерживает скрытый ввод, использовать новый файл:

```shell
node server/banking-trial.js --config server/.banking/config.json --connect --callback-file server/.banking/callback.txt
```

После появления ссылки авторизации сохранить скопированный ответ в указанный
файл. Файл не должен существовать при запуске. Программа ждёт до 10 минут.
После проверки удалить файл с одноразовым кодом.

Проба ограничена 5 EUR-счетами и 4 страницами операций на счёт. Она показывает
число записей, суммы входящих/исходящих движений и до пяти примеров на счёт.
Переводы между своими счетами пока не распознаются: суммы не следует считать
готовыми показателями расходов/доходов бюджета.

API-сессия запрашивается максимум на час, после чтения программа пытается её
закрыть. Если процесс аварийно завершён или закрытие не подтверждено, доступ
можно отозвать в банке/Enable Banking. Привязки в Control Panel сохраняются.
Операции и банковские сессии остаются только в памяти процесса, но показанные
примеры могут сохраниться в истории терминала.

Для будущего импорта стабильный ключ операции — `entry_reference`, а не
`transaction_id`; счёт между авторизациями сопоставляется по
`identification_hash`, а не временному `uid`. Понадобятся сопоставление счетов,
проверка уже внесённых вручную операций и обработка собственных переводов.
